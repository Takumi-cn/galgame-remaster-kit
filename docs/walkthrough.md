# Walkthrough: a complete synthetic session

All files in this walkthrough are generated by `python -m vnremaster demo`.
No game data is involved.

## 1. Generate fixtures

```bash
python -m vnremaster demo demo_out
```

Output:

```text
pac: demo_out/demo.pac
before: demo_out/before.png
after: demo_out/after.png
```

The archive has three zlib streams and a 14-byte footer. The images are a
deliberately soft 640×480 placeholder and a sharp full-size counterpart.

## 2. Inspect the archive

```bash
python -m vnremaster pac inspect demo_out/demo.pac
```

Example output:

```text
demo_out/demo.pac: version=3 streams=3 tail=14 bytes
 idx     offset      csize      usize   ratio
   0         12         39        768   0.051
   1         51       4107       4096   1.003
   2       4158        296       2048   0.144
```

`inspect` does not decompress the streams. It scans zlib boundaries and reports
where each stream starts and how large it is.

## 3. Verify and summarise

```bash
python -m vnremaster pac verify demo_out/demo.pac
python -m vnremaster pac stats demo_out/demo.pac
```

Example output:

```text
OK: 3 streams, version 3, footer 14 bytes, all streams decompress

demo_out/demo.pac: 3 streams, version 3, 4442 -> 6912 bytes (ratio 0.643), footer 14 bytes
size histogram: <=1 KiB=1, <=4 KiB=2, <=16 KiB=0, <=64 KiB=0, <=256 KiB=0, <=1 MiB=0, >1 MiB=0
largest streams:
     1 csize=    4107 usize=    4096
     2 csize=     296 usize=    2048
     0 csize=      39 usize=     768
duplicate payloads: none
```

`stats` decompresses every stream, so it is the slower of the two analysis
commands. It is useful for spotting duplicate assets and unexpectedly large
streams.

## 4. Rebuild one stream

Create a replacement and rebuild:

```bash
printf 'x\n' > demo_out/replacement.bin
python -m vnremaster pac rebuild demo_out/demo.pac \
  --set 0=demo_out/replacement.bin --out demo_out/modified.pac
```

Example output:

```text
wrote demo_out/modified.pac: 4468 bytes, replaced 0
```

The replacement is tiny, but the stream keeps its 39-byte compressed size.
The builder appends empty DEFLATE blocks inside the stream; it does not append
raw bytes after the zlib trailer.

Verify the result:

```bash
python -m vnremaster pac verify demo_out/modified.pac
```

## 5. Diff two archives

```bash
python -m vnremaster pac diff demo_out/demo.pac demo_out/modified.pac
```

Example:

```text
A: version=3 streams=3 | B: version=3 streams=3 | footer same
differences: 1
 idx status           A csize/usize     B csize/usize
   0 changed                 39/768              39/2
```

Use `--fail-on-diff` in CI when the command should return exit code 1 for a
difference. Use `--no-content` to skip payload hashing when only layout
changes matter.

## 6. Compare images

```bash
python -m vnremaster compare \
  demo_out/before.png demo_out/after.png \
  --out demo_out/compare.png --normalize 640x480 --zoom 2 \
  --diff-out demo_out/diff.png
```

Example output:

```text
comparison: demo_out/compare.png
size 640x480 | mean_abs_diff 16.2664 | psnr 17.29831 dB | changed 57.44% (>2) | max 246
edge_energy 12.3740 -> 23.7008 (ratio 1.915369)
diff heatmap: demo_out/diff.png
```

The sharp image has higher edge energy and a large changed fraction. That is
expected for this fixture; it does not mean “more edge energy is always
better”. Inspect the comparison sheet and the diff map.

## 7. Audit a glyph map

The example table is illustrative:

```bash
python -m vnremaster glyph check \
  --map examples/demo_map.json --text "说话门" \
  --font /path/to/japanese-font.ttf
```

On a Japanese font that lacks the Simplified forms, a typical result is:

```text
3 unique characters, 0 unmapped, 0 missing from font
  说 -> 説 (mapped, OK)
  话 -> 話 (mapped, OK)
  门 -> 門 (mapped, OK)
```

On a Chinese font that already contains the Simplified forms, the same map may
be unnecessary. The audit tells you what the font actually covers.

Generate a starter map from a font and a text corpus:

```bash
python -m vnremaster glyph plan \
  --font /path/to/japanese-font.ttf \
  --text "说话门" \
  --candidates examples/demo_map.json \
  --out demo_out/plan.json
```

The output JSON contains identity entries for characters already in the font,
candidate substitutions for characters that can reuse an existing glyph, and an
`unresolved` list for the rest.

## 8. List/capture a window (Windows only)

```bash
python -m vnremaster windows list --min-size 800x600 --limit 5
```

Example shape:

```text
        hwnd     pid         size  class / title
      0x123456    4242  1200x900  DemoWindow / Demo Game
```

Capture by handle or by filter:

```bash
python -m vnremaster windows capture --class DemoWindow --out demo_out/window.png
python -m vnremaster windows capture --hwnd 0x123456 --out demo_out/window.png
```

The capture is a read-only client-area BitBlt. It does not inject into or
modify the target process.

## 9. What to inspect in a real experiment

- Does `pac diff` report only the intended streams?
- Are all untouched streams byte-identical?
- Does the rebuilt archive still load in the target application?
- Are the comparison images normalized to the same final size?
- Does the visual crop agree with the edge-energy direction?
- Is the winning configuration recorded with a rollback path?
